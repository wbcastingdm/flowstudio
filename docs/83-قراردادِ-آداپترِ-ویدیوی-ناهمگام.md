# ۸۳ — قراردادِ آداپترِ ویدیوی ناهمگام (حلِ نیمهٔ APIِ `D-03B`)

تاریخ: **۲۲ مرداد ۱۴۰۵ (۲۰۲۶-۰۸-۱۲)**
منبع: خواندنِ ۲۲ ابزارِ `video_generation` در `~/Projects/OpenMontage/tools/video/`
(کامیت `4eab34c`). پیش‌زمینه: [`docs/82`](82-اتصالِ-OpenMontage-به-فازِ-۶.md).
پروانهٔ منبع **AGPLv3** ⇒ طبقِ `D-O16` این سند **مشاهده** است نه کد؛ پیاده‌سازیِ
TypeScript از صفر در `apps/worker` نوشته می‌شود.

سندِ ۳۰ نوشته بود «قبل از یک فراخوانِ دستیِ واقعی، نوشتنِ کدِ ویدیو حدس‌زدن است».
این سند آن حدس را برمی‌دارد: شکلِ واقعیِ چهارده مسیرِ ناهمگام این‌جاست.

## ۱. یافتهٔ حاکم — «شکلِ API» صفتِ **مسیر** است، نه مدل و نه حتی درگاه

در `docs/82` نوشتم شکلِ API صفتِ درگاه است نه مدل. خواندنِ کاملِ آداپترها این را
یک پله ریزتر کرد:

- **Veo** از راهِ گوگل دستهٔ `operation` می‌دهد و با `operation.done` تمام می‌شود؛
  همان Veo از راهِ fal.ai صف می‌دهد با `status_url`. **یک مدل، دو شکل.**
- **کلینگِ رسمی** از این هم بدتر است: *در خودِ یک فروشنده* دو مسیر دارد —
  «کلاسیک» نتیجه را در `data.task_result.<key>` می‌گذارد و با
  `GET {path}/{task_id}` نظرسنجی می‌شود؛ «توربو» نتیجه را در `data[0].outputs`
  می‌گذارد و با `GET /tasks?task_ids=<id>` نظرسنجی می‌شود.

⇒ در `packages/registry` واحدِ حملِ «شکلِ API» باید **ردیفِ مسیر** باشد:
`(provider, route)` نه `provider`. `AiProviderDescriptor` به‌تنهایی کافی نیست.

## ۳. جدولِ حقیقت — شکلِ واقعیِ هر مسیر

| مسیر | ثبتِ کار | شناسه از کجا | نظرسنجی | موفقیت | شکست |
|---|---|---|---|---|---|
| **fal.ai صف** (veo/kling/minimax/seedance) | `POST queue.fal.run/fal-ai/<model>` | `status_url` + `response_url` **هر دو در پاسخ** | `GET status_url` | `COMPLETED` | `FAILED`, `CANCELLED` |
| **گوگل مستقیم** (veo) | SDKِ `google-genai` | دستهٔ `operation` | `operation.done` | `done == true` | استثنا |
| **کلینگ کلاسیک** | `POST <path>` | `data.id` | `GET <path>/<id>` | `task_status` == موفق | `task_status` == ناموفق |
| **کلینگ توربو** | `POST <path>` | `data.id` | `GET /tasks?task_ids=<id>` | `data[0].status` | همان |
| **رانوی** | `POST /v1/text_to_video` | `id` | `GET /v1/tasks/<id>` | `SUCCEEDED` | `FAILED` + `failureCode` |
| **ریپلیکیت** (seedance) | `POST /v1/models/<slug>/predictions` | `urls.get` ← **خودتوصیف** | همان `urls.get` | `succeeded` | هرچه ≠ succeeded |
| **OpenAI سورا** | `client.videos.create_and_poll()` | `video.id` | **داخلِ SDK پنهان** | `completed` | هر چیزِ دیگر |
| **xAI گراک** | `POST /v1/videos` | `request_id` | `GET /v1/videos/<id>` | `done` | `failed`, **`expired`** |
| **هیگزفیلد** | `POST /v1/generations` | `id` (+ `status_url` اختیاری) | `status_url` | `Completed`/`COMPLETED` | `Failed`, **`NSFW`**, `Cancelled` |
| **هایجن** | گردش‌کارِ اجرا | `execution_id` | `GET /v1/workflows/executions/<id>` | `completed` | `failed`, `error` |
| **جیمنگ/ولکانو** | `POST` امضاشده | `data.task_id` | امضاشده | `done` | `not_found`, `expired` |
| **جمنای Omni** | Files API | نامِ فایل | `state` | ≠ `PROCESSING` | استثنا |

### حرف‌های این جدول

**۱) هفت واژگانِ متفاوت برای «تمام شد».**
`COMPLETED` · `SUCCEEDED` · `succeeded` · `completed` · `Completed` · `done` (رشته)
· `done` (بولین). هیچ استانداردی نیست — حتی حروفِ بزرگ و کوچک هم یکی نیست.
⇒ نگاشتِ حالت **باید جدولِ داده باشد**، نه `switch` در کد.

**۲) دو حالتِ پایانی که «شکست» نیستند و کدِ ما باید جدایشان کند:**
- 🔴 **`NSFW` در هیگزفیلد** — ردِ سیاستِ محتوا، نه خرابیِ فنی. تلاشِ دوباره با
  همان پرامپت **همیشه** شکست می‌خورد. باید به گیتِ کنترلِ محتوای `D-203` وصل شود،
  نه به حلقهٔ failover. اگر مثلِ خطای فنی با آن رفتار کنیم، سه بار پول می‌دهیم
  بابتِ سه ردِ قطعی.
- 🔴 **`expired` در گراک و جیمنگ** — کار موفق بوده ولی نتیجه‌اش جمع‌آوری شده.
  یعنی **دیر رفتیم سراغش**. این خطای ما است نه فروشنده؛ باید هشدارِ عملیاتی بدهد.

**۳) فقط ریپلیکیت نشانیِ نظرسنجی را خودش برمی‌گرداند** (`urls.get`). بقیه یا باید
نشانی را بسازیم یا از میدانِ دلخواهِ پاسخ برداریم. ریپلیکیت درست‌ترین طراحی را
دارد؛ الگویِ ما باید اجازه بدهد نشانی **یا** ساخته شود **یا** از پاسخ خوانده شود.

**۴) fal.ai تنها جایی است که «وضعیت» و «نتیجه» دو نشانیِ جدا دارند**
(`status_url` و `response_url`). بقیه هر دو را از یک پاسخ می‌دهند.

**۵) سورا نظرسنجی را داخلِ SDK پنهان کرده** (`create_and_poll`). یعنی برای آن
کنترلی روی بازه و مهلت نداریم مگر با نوشتنِ حلقهٔ خودمان. برای گاردریلِ CPAS این
مسیر **کور** است — هزینهٔ هر تلاش را نمی‌شود ریز ثبت کرد.

**هر مسیر مهلتِ اجباری دارد**، حتی اگر مرجع نداشته باشد.

⭐ **فقط هایجن پس‌رفتِ نمایی دارد.** بقیه با بازهٔ ثابت می‌کوبند. برای رندری که
۳ دقیقه طول می‌کشد، بازهٔ ثابتِ ۳ ثانیه یعنی ۶۰ فراخوانِ بیهوده. الگویِ هایجن
درست است و باید **پیش‌فرضِ ما** شود، نه استثنا.

## ۵. قراردادِ پیشنهادی برای `apps/worker`

سه تابعِ خالص به‌ازای هر مسیر، به‌علاوهٔ یک ماشینِ حالتِ مشترک. تمامِ تفاوتِ
فروشنده‌ها در **داده** می‌نشیند، نه در شاخهٔ کد — همان قاعدهٔ «مدل ردیفِ داده است»
که فازِ ۱ گذاشته بود.

```ts
type TerminalKind =
  | 'succeeded'
  | 'failed'          // خرابیِ فنی — قابلِ تلاشِ دوباره
  | 'rejected'        // ردِ سیاستِ محتوا (NSFW) — تلاشِ دوباره ممنوع
  | 'expired'         // نتیجه جمع‌آوری شد — دیر رفتیم
  | 'timeout';

interface VideoRoute {
  provider: string;              // 'kling'
  route: string;                 // 'turbo' | 'classic'
  submit(req: GenRequest): Promise<{ taskId: string; statusUrl?: string; resultUrl?: string }>;
  poll(h: Handle): Promise<{ kind: 'pending' } | { kind: TerminalKind; detail?: string }>;
  fetch(h: Handle): Promise<{ videoUrl: string }>;

  // داده، نه کد:
  pollIntervalMs: number;        // شروع
  pollBackoff: number;           // ۱٫۲ پیش‌فرض — درسِ هایجن
  pollMaxIntervalMs: number;     // ۳۰۰۰۰
  timeoutMs: number;             // اجباری، حتی اگر مرجع نداشته باشد
  terminalStates: Record<string, TerminalKind>;   // نگاشتِ هفت‌واژگانی
}
```

**چرا `rejected` از `failed` جدا است:** بدونِ این تفکیک، حلقهٔ failover یک ردِ
سیاستی را سه بار تکرار می‌کند و سه بار پول می‌دهد. این دقیقاً همان
[نقطهٔ درجِ اجباریِ اسپرینتِ ۳](81-مدل-ارکستراسیون-و-قرارداد-جدایش.md) است که
`ai-gateway.service.ts` در `catch` هیچ `release()`ی ندارد — و آن‌جا فعلاً بی‌خطر
است چون TEXT رایگان است، ولی **ویدیو رایگان نیست**.

## ۶. سه چیزی که این سند حل نمی‌کند

1. **کدام تجمیع‌کننده.** هیچ‌کدام از این ۱۴ مسیر تجمیع‌کنندهٔ ایرانیِ `D-C04`
   (۹روتر، آوالای، گپ‌جی‌پی‌تی) نیست. نیمهٔ دومِ `D-03B` همچنان بازِ منتظرِ مالک.
2. **هزینه و تأخیرِ واقعی.** صورت‌کسرِ CPAS از این‌جا درنمی‌آید؛ کلیدِ واقعی
   می‌خواهد.
3. **نشانیِ ویدیو موقتی است.** کامنتِ خودِ رانوی: «۲۴ تا ۴۸ ساعت». پس معماریِ ما
   باید **بلافاصله** فایل را به انبارِ خودمان بکشد، نه اینکه نشانی را در دیتابیس
   ذخیره کند. این یک قیدِ طراحی است نه جزئیاتِ پیاده‌سازی.

## ۷. کارِ بعدی

1. مالک `D-03B` (کدام تجمیع‌کننده) و `D-O16` (پروانه) را ببندد.
2. جدولِ بخشِ ۳ به مهاجرتِ `packages/registry` تبدیل شود: کلیدِ `(provider, route)`
   به‌علاوهٔ `terminalStates` به‌عنوانِ ستونِ JSON.
3. `apps/worker` قراردادِ بخشِ ۵ را پیاده کند — با پس‌رفتِ نمایی به‌عنوانِ پیش‌فرض
   و مهلتِ اجباری روی همه.
4. `RegionReachable` از **سرور** اندازه‌گیری شود، نه از مک.
