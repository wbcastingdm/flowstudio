# FlowStudio

ارکستراتورِ تولید ویدیو با هوش مصنوعی — از ایده تا دیده. از تیزرِ چندثانیه‌ای
تا روایتی به‌درازای یک فیلمِ کامل، در یک چرخه.

پروژهٔ **مستقل**. از مخزنِ ماژول‌های وبکستینگ قطعه برمی‌دارد، ولی هیچ وابستگیِ اجرایی
به آن ندارد و هرگز API وبکستینگ را صدا نمی‌زند. جهتِ اتصال برعکس است: وبکستینگ
به‌عنوانِ کانالِ توزیع، FlowStudio را صدا می‌زند.

---

## وضعیتِ امروز (۱۸ مرداد ۱۴۰۵)

**زنده: https://flowstudio.webcasting.ir**

| بخش | حال |
|---|---|
| طراحیِ کاملِ رابط (فرود + پنلِ ۴ مرحله‌ای + پنلِ مدیریت) | ✅ در `prototype/` |
| صفحهٔ فرودِ واقعی (Next.js) | ✅ زنده |
| فرمِ تماس با ذخیرهٔ سرنخ | ✅ زنده — JSONL روی والیوم |
| HTTPS + بلوکِ nginx روی سرورِ وبکستینگ | ✅ گواهی گرفته شد، reload شد |
| API، دیتابیس، صف، احرازِ هویت، موتورِ ویدیو، پنلِ مدیریت | ❌ هنوز هیچ |

از چهار مرحلهٔ پروتوتایپ **هیچ‌کدام** هنوز کار نمی‌کند؛ `/app` عمداً همین را
صادقانه می‌گوید. فهرستِ کاملِ کارهای مانده با معیارِ تمام‌شدن:
**[`docs/30-وضعیت-و-کارهای-مانده.md`](docs/30-وضعیت-و-کارهای-مانده.md)** ← اول این را بخوان.
گسترشِ دامنهٔ محصول تا فرم‌بلند + بازآراییِ فولدر:
**[`docs/40-گسترشِ-دامنه-تا-فرم‌بلند-و-بازآراییِ-فولدر.md`](docs/40-گسترشِ-دامنه-تا-فرم‌بلند-و-بازآراییِ-فولدر.md)**.

دامنهٔ `flowstudio.ir` ثبت شده و روی Cloudflare است، ولی **عمداً دست‌نخورده می‌ماند**
و به هیچ موتورِ جست‌وجویی معرفی نمی‌شود تا محصول واقعاً کار کند.

## ساختار

```
apps/web/          صفحهٔ فرود و پنل (Next.js 14، RTL، وزیرمتن embedded)
deploy/            Dockerfile compose + کانفیگِ nginx برای زیردامنه
prototype/         پروتوتایپِ اصلیِ لوکال — سندِ مرجعِ طراحی، دست‌نخورده
docs/              ارزیابی، سندِ طراحی، تصمیم‌های باز
```

`prototype/index.html` را مستقیم در مرورگر باز کنید؛ خودبسنده است و همهٔ سه نما
(سایتِ معرفی / پنلِ کاربر / پنلِ مدیریت) را زنده نشان می‌دهد. این فایل **ویرایش نمی‌شود** —
مرجعِ طراحی است، نه کدِ محصول.

## اجرا

```bash
cd apps/web && npm install && npm run dev     # http://localhost:3100
```

## دیپلوی (فاز ۰ — فقط وب)

```bash
rsync -az --delete --exclude node_modules --exclude .next --exclude .git \
  ./ root@62.220.123.55:/opt/flowstudio/
ssh root@62.220.123.55 \
  'cd /opt/flowstudio && docker compose -p flowstudio -f deploy/docker-compose.prod.yml up -d --build'
```

نامِ پروژهٔ `-p flowstudio` مهم است: کانتینر، شبکه و والیومِ ما را از وبکستینگ جدا نگه می‌دارد.

بررسی بدونِ DNS:

```bash
ssh root@62.220.123.55 'curl -s -o /dev/null -w "%{http_code}\n" http://172.18.0.1:3100/'
```

### سه گامِ باقی‌ماندهٔ رو‌آمدن روی زیردامنه

۱. **DNS** — رکوردِ `A` برای `flowstudio.webcasting.ir` → `62.220.123.55` در Cloudflare.
   (این تنها گامی است که از راهِ سرور انجام‌شدنی نیست.)
۲. **گواهی** — با همان روشِ بقیهٔ زیردامنه‌ها؛ دستورش در
   `deploy/nginx/flowstudio.webcasting.ir.conf` نوشته شده.
۳. **بلوکِ nginx** — nginx روی این سرور **کانتینر** است و کلِ کانفیگش یک فایلِ
   واحد است. محتوای همان فایل باید به انتهای
   `/opt/webcasting-platform/deploy/turkey/nginx.conf` اضافه شود، سپس:
   `docker exec wbc_nginx nginx -t && docker exec wbc_nginx nginx -s reload`
   — **بدونِ reload هیچ اثری ندارد.**

## قاعده‌های حاکم

1. **هرگز به کانتینرها، شبکه یا دیتابیسِ وبکستینگ دست نزن.** پروژه مستقل است و
   روی همان سرور فقط هم‌خانه است.
2. **جهتِ اتصال:** FlowStudio ← وبکستینگ. وبکستینگ با کلیدِ `wsk_*` صدا می‌زند و
   نتیجه را با وبهوک می‌گیرد. هرگز برعکس.
3. **پروتوتایپ سندِ حقیقتِ طراحی است.** هر تغییرِ رابط اول آنجا معنا پیدا می‌کند.
4. تا وقتی محصول کار نمی‌کند، `noindex` روی همه‌چیز باقی می‌ماند.
