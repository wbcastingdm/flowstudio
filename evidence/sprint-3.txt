■ ۱) کیفِ نو خالی است و رزرو روی آن رد می‌شود
✅ موجودیِ اولیه  →  {"balance":0,"held":0}
✅ رزرو بدونِ موجودی  →  موجودیِ سکه کافی نیست — 100 سکه لازم است و 0 موجود است.
✅ بعد از رزروِ ناموفق دست‌نخورده  →  {"balance":0,"held":0}

■ ۲) شارژ و رزرو
✅ بعد از شارژ  →  {"balance":1000,"held":0}
✅ رزرو از balance به held منتقل می‌کند  →  {"balance":700,"held":300}

■ ۳) تسویه با خرجِ کمتر — باقی‌مانده برمی‌گردد
✅ ۳۰۰ رزرو، ۱۸۰ خرج ⇒ ۱۲۰ برگشت  →  {"balance":820,"held":0}

■ ۴) آزادسازی کلِ رزرو را برمی‌گرداند (گاردریلِ ۶)
✅ بعد از رزرو  →  {"balance":320,"held":500}
✅ بعد از آزادسازی همه‌چیز سرِ جایش  →  {"balance":820,"held":0}

■ ۵) بی‌اثر در تکرار — `release` دو بار سکه نمی‌سازد
✅ آزادسازیِ دوباره noop است  →  true
✅ موجودی عوض نشد  →  {"balance":820,"held":0}

■ ۶) خرجِ بیشتر از رزرو ممنوع است
✅ تسویهٔ ۱۵۰ روی رزروِ ۱۰۰  →  خرجِ واقعی (150) از رزرو (100) بیشتر شد — پاکت پیش از شروع بسته شده بود.

■ ۷) پاکتِ بودجه — D-006 و وارونگیِ بودجه
✅ پاکتِ بدونِ سقف گامِ پولی نمی‌گیرد  →  سقفِ بودجهٔ این گروه تعیین نشده — تا عددِ سقف ثبت نشود هیچ گامِ پولی شروع نمی‌شود (D-006).
✅ رزروِ دوم از سقفِ پاکت رد می‌شود  →  پاکتِ بودجه جا ندارد: سقف 400، خرج‌شده 0، رزروشده 250، درخواست 250.
✅ خرجِ ثبت‌شدهٔ پاکت  →  {"spent":300,"reserved":0}

■ ۸) `runWithHold` — شکست سکه نمی‌بلعد
✅ بعد از شکست، موجودی دقیقاً مثلِ قبل  →  {"balance":520,"held":0}
✅ نتیجهٔ اجرایِ موفق  →  "خروجی"
✅ فقط خرجِ واقعی کسر شد  →  400

■ ۹) دفتر با موجودی جمع می‌خورد
✅ Σ دفتر = balance + held  →  400
   (15 ردیفِ دفتر ثبت شد)

■ ۱۰) صفِ کار — یک کار فقط به یک کارگر می‌رسد
   وضعیتِ صف: {"PENDING":0,"RUNNING":0,"DONE":0,"FAILED":0}

✅ همهٔ بندها گذشت
